# Validation Report Format

This document defines the structure for the validation report written by the
generated `[repo]-test-orchestrator` skill after each pipeline run.

## File Location

`plan/{category}/{quarter}/{planTicket}-validation.md`

Where `category` and `quarter` are derived from the resolved plan file path.

---

## Document Structure

```markdown
---
ticket: {planTicket}
plan-file: {resolved plan file path}
type: {planType}
quarter: {planQuarter}
functional_area: {planArea}
validator-severity: {GREEN | YELLOW | RED}
generated_by:
  model: {model name}
  tool: {tool name}
  timestamp: {ISO 8601}
---

# Implementation Validation Report — {planTicket}
```

## Severity Legend

| Severity | Condition | Action |
|---|---|---|
| **GREEN** | `gapFiles[]` is empty AND `regressionRisks[]` is empty | Proceed to PR |
| **YELLOW** | `gapFiles[]` ≤ 2 AND `regressionRisks[]` is empty | Review Remaining Actions, close gaps before PR |
| **RED** | `gapFiles[]` > 2 OR `regressionRisks[]` is not empty | Address all P1 actions before PR |

## Status Icons

| Icon | Meaning |
|---|---|
| ✅ | Satisfiable — test file found or scenario covered by planned tests |
| ⚠ | Gap — test file missing or scenario has no planned coverage |
| ⏳ | Unverifiable — file existence cannot be confirmed in this session |
